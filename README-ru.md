# lantern-headless-iran

[English](./README.md) · [فارسی](./README-fa.md) · **Русский**

> **Неофициальный** форк [`getlantern/lantern-headless-client`](https://github.com/getlantern/lantern-headless-client).
> Проект не связан с командой Lantern.

Клиент Lantern **без графического интерфейса** (headless), созданный для сетей с жёсткой
фильтрацией (проверено в Иране). Он открывает два локальных порта, к которым подключается ваш
браузер — трафик уходит через сеть Lantern.

## Когда это помогает — а когда нет

- **В регионах с жёсткой фильтрацией, где серверы самого Lantern заблокированы по IP, эта
  программа сама по себе НЕ обходит фильтр.** Без рабочего `--upstream-proxy` её соединения
  просто не проходят — это не «установил и открываешь любые сайты».
- **Что она умеет в таких условиях: получать подходящий IP через ваш upstream.** Короткое
  соединение к (заблокированным) серверам Lantern идёт через ваш здоровый прокси, а трафик
  продолжает идти собственным протоколом Lantern и выходит с подходящим IP.
- Значит, для такой сети нужен уже работающий прокси (Tor, Psiphon, ретранслятор, …), а этот
  клиент — способ получить хороший IP через этот upstream.

## Скачивание

Бинарные файлы **собираются автоматически средствами GitHub Actions** и публикуются на странице
[Releases](https://github.com/FossilizedProgrammer/lantern-headless-iran/releases).
Ничего не загружается с чьего-либо компьютера вручную:

| Файл | Платформа |
|---|---|
| `lantern-headless-linux-amd64` | Linux, x86_64 |
| `lantern-headless-windows-amd64.exe` | Windows, 64 бит |

Как это работает: каждый push в `main` собирает оба бинарника (чтобы сборка всегда была рабочей),
а каждый тег версии `v*` дополнительно создаёт **Release** с этими же двумя файлами.

## Быстрый старт

1. Скачайте файл для вашей системы со страницы **Releases**.
2. Запустите его. В примере ниже предполагается, что у вас уже работает локальный прокси
   (Tor, Psiphon, …) на порту `1080`:

**Linux**

```shell
chmod +x lantern-headless-linux-amd64
./lantern-headless-linux-amd64 --data-path ./data --upstream-proxy socks5://127.0.0.1:1080 \
  start --http-proxy-addr 127.0.0.1:18070 --socks-proxy-addr 127.0.0.1:18071
```

**Windows (Command Prompt)**

```bat
lantern-headless-windows-amd64.exe --data-path data --upstream-proxy socks5://127.0.0.1:1080 start --http-proxy-addr 127.0.0.1:18070 --socks-proxy-addr 127.0.0.1:18071
```

`--upstream-proxy` необязателен, но в фильтруемых сетях настоятельно рекомендуется. Поддерживаются
схемы `socks5://`, `http://` и `https://`; флаг работает сразу в трёх ролях: получение конфига,
само подключение к серверам Lantern (их IP часто заблокированы) и запасной канал для трафика.

3. Настройте браузер на локальные порты:

**Firefox** (рекомендуется — локальный DNS обычно отравлен):
`Настройки → Основные → Настройки сети → Ручная настройка прокси` → SOCKS Host `127.0.0.1`,
порт `18071`, тип **SOCKS v5**, включите **«Использовать DNS через SOCKS5»**.

**Chrome/Chromium**

```shell
google-chrome --proxy-server="socks5://127.0.0.1:18071"
```

> Клиент работает без интерфейса и никогда не меняет настройки системы сам. Если браузер не
> настроен, трафик пойдёт напрямую и не пройдёт через фильтр.

## Что означают сообщения при запуске

```
SUCCESS  Control plane reachable (config fetched successfully)
INFO     Local proxy is listening — SOCKS5: 127.0.0.1:18071  HTTP: 127.0.0.1:18070
SUCCESS  Data path OK — HTTP 204 from https://www.google.com/generate_204 in 803ms
INFO     Traffic leaves this machine through IP 31.171.100.110
```

- **Control plane reachable** — конфиг получен. Это ничего не говорит о трафике браузера.
- **Local proxy is listening** — порты открыты (открыт ≠ работающий).
- **Data path OK / NOT working** — самая важная строка: клиент выполнил реальный запрос через свой
  прокси. Если написано `NOT working`, следующая строка `Hint:` подскажет, что исправить.
- **Traffic leaves this machine through IP …** — тот публичный IP, который видит сайт назначения.

## Команды

| Команда | Что делает |
|---|---|
| `start` | Запускает локальные порты HTTP + SOCKS5 |
| `update [--via upstream\|direct\|auto] [--check] [--json]` | Обновляет сохранённый список серверов |
| `servers [--refresh] [--check] [--json]` | Список серверов со страной/городом; `--check` показывает доступность |
| `start --server <name>` | Привязывает подключение к одному серверу (без автопереключения!) |
| `auth login / signup / logout` | Вход / регистрация в Lantern |
| `--help`, `--version` | Справка и версия |

Примеры (глобальные флаги ставятся **до** команды):

```shell
./lantern-headless-linux-amd64 --data-path ./data update --via upstream
./lantern-headless-linux-amd64 --data-path ./data servers --check
./lantern-headless-linux-amd64 --data-path ./data start --server sunny-tokyo-02
```

## Основные параметры

| Параметр | Значение |
|---|---|
| `--upstream-proxy` | Ваш рабочий прокси: получение конфига, доступ к серверам Lantern, запасной канал |
| `--data-path` | Где хранятся конфиг и логи (по умолчанию `~/.lantern-headless`) |
| `--server <name>` | Привязка `start` к одному серверу (см. `servers`) |
| `--with-proxyless` | Дополнительно пробовать прямой/умный дозвон для запросов управления (выключено по умолчанию) |
| `--debug` / `--quiet` / `--raw` | Уровень логирования |

Полный список: `--help`.

## Решение проблем

- **`update` не работает** — попробуйте `--via direct`; если и это не помогло, укажите
  `--upstream-proxy` с рабочим прокси (прямой доступ к сервису конфигов обычно заблокирован).
  Ошибка `HTTP 401/403` означает: сначала выполните `auth login`.
- **`bind: address already in use`** — порт занят; укажите другие порты в
  `--http-proxy-addr` / `--socks-proxy-addr`.
- **SOCKS подключается, но страницы не открываются** — серверы Lantern недоступны из вашей сети;
  включите `--upstream-proxy`. Если в логе видно `Fell back to the upstream proxy`, трафик выходит
  через ваш прокси, а не через сеть Lantern.
- **Сайт резолвится в `10.x.x.x`** — локальный DNS отравлен; клиент это замечает и разрешает имя
  хоста на стороне сервера (строка в логе: `keeping the hostname so it is resolved remotely`).

## Сборка из исходников

Нужен [Go](https://go.dev/dl/) версии 1.24 или новее:

```shell
go build -o bin/lantern .
./bin/lantern --help
```

## Чем этот форк отличается от оригинала

- **`--upstream-proxy` работает сразу во всём**: получение конфига, открытие (часто заблокированного)
  TCP-соединения с серверами Lantern и запасной канал для трафика — локальные порты отвечают, даже
  когда ни один сервер Lantern напрямую недоступен.
- **Защита от отравленного DNS**: приватный IP от локального DNS никогда не набирается напрямую;
  имя хоста сохраняется и разрешается удалённо на сервере.
- **Команды `servers` и `update`**: список серверов с географией, проверка доступности и привязка
  `start` к одному серверу.
- **Честная диагностика**: перед тем как сообщить о работе, клиент делает реальный запрос через
  прокси.
